## v0.5.7 - Under construction ⚠️: no ISRC queue stalls; strict whole-album quality guarantee

The user reports that some downloads stall, suspected ISRC fallback, and reiterates that an album must be entirely skipped if any track is unavailable at selected quality. Identified unbounded `while (failedTrack.albumsFallback.length)` loop that did not count unsuccessful album probes toward the 20-attempt ceiling, and unbounded `get_track_with_fallback` / public ISRC lookup / search metadata calls. The native fallback inside `getPreferredBitrate` also used a cyclic/unbounded `do...while` when Deezer tracks referred to each other.

New core `v3.14.5`, GUI `v0.5.7` changes: shared `withFallbackTimeout` helper in `packages/deemix/src/utils/fallbackTimeout.ts`, per-request timeout 5s and ISRC shared 15s metadata work budget, cap alt-album probes at 3 including misses, ISRC candidate attempts at 3, search pages at 2; limit native gateway fallback traversal to 3 unique IDs/12s and prevent cycles. Ordinary audio streaming is never given an artificial total-duration timeout. The core direct ISRC cache API request is bounded and cached inflight promises are cleared after timeout. Further metadata-search fallback (if enabled separately) is bounded. All track-level fallback/probe unknowns must finish as a marked failure (not a stalled queue worker).

Strict album mode (`dontDownloadIncompleteReleases`, Settings > Downloads > **Don't download incomplete releases**): before creating any output media file or running album downloads, preflight *all* tracks at the selected quality with `requireExactBitrate=true` (no downgrade even when fallbackBitrate is on). Per-track preflight is bounded 12s; only affirmative `probeAvailable===true` with exactly selected format allows album. A lower-quality result, unavailable track, indeterminate probe, timeout or preflight exception skips the WHOLE album with an explicit log/queue reason and **0 downloaded tracks**, preserving any previously downloaded files. This is a fail-closed design, necessary to satisfy the user's rule. It cannot guarantee that a real audio stream will not fail later despite passing a URL availability probe, but it must not knowingly start an incomplete release. Feature remains optional and does not silently toggle user preferences.

Regression tests in `downloader.test.ts`, `fallbackTimeout.test.ts`, `isrcCache.test.ts`. Any pending user acceptance for v0.5.6 does not carry to v0.5.7. Do not modify GitHub Actions workflow files. Release only after CI, Windows packaged startup and asset checks. ## v0.5.8 - Under construction ⚠️: transactional exact-quality album downloads (2026-10-12)

**Reported real Deezer case:** https://www.deezer.com/en/album/53346642, track 440060362, Inna - "My Dreams": "Your account can't stream the track from your current country and no alternative found." User requires an entire album to be discarded if ANY track cannot be obtained at the selected quality. v0.5.7's fail-closed preflight prevented many incomplete albums but did **not** remove tracks downloaded before a subsequent stream/quality failure.

**Behavior:** With Settings > Downloads > **Don't download incomplete releases** enabled, the preflight stays mandatory. After preflight the whole album is downloaded and tagged in a uniquely owned directory `.deemix-incomplete-*` inside the selected download root. Every result is checked for a unique, nonempty downloaded audio file and **exact** selected format (no bitrate downgrade). Failed/geoblocked tracks, canceled downloads, failures after preflight and unexpected errors discard the entire stage. All complete tracks, covers, optional lyrics and auxiliary files publish only after all checks pass, using hardlink publication with ownership proof and compensating rollback on errors. No preexisting audio is removed or overwritten, even when an overwrite setting is enabled: collisions abort strict-mode publication rather than risk data loss. The file-backed staging marker permits cleanup/recovery of a dead process's partial publication by unlinking **only** destination paths proven to reference the private stage inode. Track counts are reset to zero if rolled back and the queue marks incomplete strict albums as FAILED, not complete; after commit final paths are reported. Post-download custom commands execute only after successful publication. Other track/playlist and nonstrict paths are unchanged.

**Tests:** `packages/deemix/src/utils/releaseTransaction.test.ts`: private stage success, failure discards staged audio but not original, existing-output collision, recovery of partial published hardlinks, preflight georestriction for the user-provided track 440060362, late georestriction after a successful first track and wrong-quality after preflight.
