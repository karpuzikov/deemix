# Deemix GUI continuity

Version: 0.5.0 initially; planned hardening version 0.5.1, status under construction. Entry: packages/gui/src/main.ts, src/preload.ts, scripts/build.js; Electron Forge packaging in forge.config.js. ## v0.5.3 - Under construction ⚠️: persistent desktop login

Root cause: Electron did not enable `DEEMIX_SINGLE_USER`, while earlier security changes removed persistent browser `localStorage` ARL storage and kept only ephemeral `sessionStorage`. Backend `saveLoginCredentials`/`getLoginCredentials` already uses Windows DPAPI. Fix: enable `DEEMIX_SINGLE_USER=true` by default for loopback-only Electron GUI before importing `deemix-webui`; respect explicit env overrides, default false for network-facing hosts. Valid login persists as Windows DPAPI-protected `Documents\\Karpuzikov Tools\\Deemix\\login.json` and restores on next startup via `/api/connect` then `/api/loginArl`. Logout clears the saved login. Test simulates new Express app after restart and ensures login+download, logout removal, and no multi-user persistence. User must login one final time after upgrade if prior protected credentials do not exist. GUI v0.5.3 - Under construction ⚠️ until manual acceptance.
