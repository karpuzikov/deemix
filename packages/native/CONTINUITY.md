## Native queue implementation - experimental

- Isolated persistence under dynamically resolved `Documents/Karpuzikov Tools/Deemix Native/queue.json`; atomic JSON writes. Saved rows and Pause survive restart; interrupt-in-progress rows change to stopped after recovering staged files. No automatic downloading on startup.
- Controls: add URL, pause after current release, stop/terminate process tree, resume queued and stopped entries, remove errored entries without deleting downloaded music. UI shows status and activity on a compact dark Tkinter window, with a folder-open control immediately before path inputs.
- Each attempted CLI item downloads to a private per-job staging folder. Final output is installed using exclusive hard links from named per-file `.part` ownership witnesses. Rollback deletes only files verified by filesystem identity as owned by the transaction, and preserves unrelated and pre-existing target files; name collisions abort rather than overwrite. Pending transaction state is durably journaled and recovery refuses unauthenticated staging cleanup.
- Staging is per queued URL, **not yet per release when a URL expands to multiple albums**. Artist/discography release granularity, parallel streams, accurate track-count reconciliation, format verification, and native Deezer session reuse are major open blockers.
- A successful CLI return code is **not** enough to prove every album track is present in the selected quality. Current native prototype has **no certified album completeness guarantee**. Users should keep the existing v0.5.7 release for real downloads until these gates pass.

### Control contract, v0.4.7

- `Download to...` single-item and mixed checked batch: mandatory ONE folder chooser. Cancel queues nothing. After folder chosen, queue entry is persisted and queue immediately unpaused if Deezer is authenticated, so the background download starts without another Resume click. If not signed in (including saved login in progress), remember explicit intent in-process and auto-start after a successful login; do not auto-start unrelated persisted queue on a new app launch.
- Queue `Start downloads` / `Resume`: visible only if stopped/queued work exists, paused and not currently running. `Pause after this release`: prevent the next release from starting, allow current release to finish. `Stop current`: stop current download and roll back its incomplete staging; retain queued/stopped entries for later. `Cancel all`: confirm, pause queue, remove queued/stopped entries, stop current and clean owned staging after its worker exits, preserve fully published existing albums. Do not conflate Stop and Cancel.
- `Clear finished`: clears completed/canceled history only, leaves errors available for retry. `Remove errors`: clears error entries separately. Retry selected reenqueues and begins if already authenticated. `Change destination...` is only an available right-click action on a non-running queue row, not a confusing mixed global Download to button. `Open destination folder` is separate and is the folder icon next to each path.

Preflight checks show their phase rather than inflating completed-track counts. Live row updates no longer destroy and re-create the whole queue widget on every track. Stop/error resets processed count after rollback.
- Error table column fixed 158px with short elided message and full tooltip, rather than taking disproportionate space. Segoe UI 10pt applied as Qt default and existing Fluent QSS preserved (real font appearance NOT verified).

Original supported tokens include year/artist/album/upc; unknown template tokens are rejected explicitly rather than becoming literal percent strings.
